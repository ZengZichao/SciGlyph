# Deploying to GitHub Pages

The SciGlyph gallery is a **build-free** static site: `index.html` inlines the whole
asset index, and thumbnails reference the SVGs directly through relative
`assets/…` paths. There is no bundler, no CDN and no backend, so Pages only has to
serve the files as they are.

## 1. Verify locally (run this set before publishing)

```bash
python3 tools/check_repo.py        # asset + metadata gate (incl. renderability)
python3 tools/check_site.py        # gallery index matches assets/, page is self-contained
python3 tools/build_site.py        # assemble the publishable artifact into site/
python3 -m http.server -d site 8000  # local preview
```

Open <http://localhost:8000/> for the exact experience served online.
`site/` is a rebuildable artifact and is git-ignored — never commit it.

> Double-clicking `index.html` also works (the gallery uses no `fetch`), but Pages
> serves over HTTP, so confirm with the http preview before publishing.

## 2. Turn Pages on

Live site: <https://zengzichao.github.io/SciGlyph/>

The site currently uses **branch deployment** (build-free, and all this project needs):

1. In **Settings → Pages → Build and deployment**, choose Source =
   *Deploy from a branch*, branch `main`, folder `/` (root).
2. GitHub then builds the `main` root, i.e. `index.html` + `assets/` + `preview/`.
3. Every later push to `main` republishes automatically.

### Optional: deploy via Actions so the quality gates run first

This repository ships `.github/workflows/pages.yml`: it runs `check_repo.py` and
`check_site.py` first, stages `site/` with `build_site.py`, then publishes — any gate
failure aborts the deployment, so broken assets cannot go live.

To switch to it:

1. Change Source from *Deploy from a branch* to **GitHub Actions**.
2. Push the workflow file. Note that GitHub requires the `workflow` OAuth scope to
   create workflow files through the API/token; if it is missing, run
   `gh auth refresh -s workflow`, or add the file in the web UI
   (*Add file → Create new file*) and paste `.github/workflows/pages.yml`.
3. Pushes to `main` then show up in **Actions** as "Deploy gallery to Pages", whose log
   ends with the `Page URL`. You can also trigger "Run workflow" manually.

Both routes serve identical content. With branch deployment only, run the gates
locally before pushing.

## 3. After changing assets

| What changed | Re-run |
|---|---|
| SVGs under `assets/**` | `python3 tools/check_repo.py` |
| names / descriptions / tags in `manifest.json` | `python3 tools/reorg/build_gallery.py` to regenerate `index.html` |
| assets added or removed | `build_gallery.py` + `check_site.py` |
| README / SPEC / NOTICE | `python3 tools/reorg/docs_gen.py` |

`index.html` is generated by `tools/reorg/build_gallery.py`; edit the generator or the
manifests instead, otherwise the next run overwrites your edits.

## 4. Limits and access

- Project Pages sites are public to anyone with the URL; the free plan cannot
  password-protect them.
- The soft limits are 1 GB per site and 100 GB of monthly bandwidth. This build is
  about 11 MB across 3,090 SVGs averaging 2.4 KB — far below both.
- The `.nojekyll` file at the repo root makes Pages skip Jekyll, so no
  underscore-prefixed path is ever dropped; `build_site.py` writes one into `site/` too.
